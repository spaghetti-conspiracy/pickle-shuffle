# 対戦カード生成アルゴリズム

`doc/spec.md` の要求を、どう計算に落としたかの説明。実装は `app/scheduler/` にあり、
DB と Web には依存しない。

## 1. 解いている問題

1ラウンド（全コート分）ごとに、次を決める。

- **誰が出るか** — 出場可能なメンバーから、コート数 x 4 名を選ぶ
- **どう組むか** — 選んだ人をペアに分け、ペア同士を対戦させ、コートに割り当てる

これを練習会が終わるまで繰り返す。1試合7分、3時間で25ラウンド程度。
メンバーは遅刻・中座・休憩で入れ替わるので、そのつど今いる人だけで組み直す。

難しいのは、良し悪しの基準が7つあり互いに衝突することと、
1ラウンドだけを最良にしても練習会全体では最良にならないこと。

## 2. 全体の流れ

```
採用済みラウンドのスナップショット
        │
        ▼
   統計の導出          出場回数・休憩クレジット・連続不参加・休み明け
        │
        ▼
   出場者候補の決定     公平性のハードな枠で絞る
        │
        ▼
   組み分け            1試合ずつ決める（コート数に依存しない）
        │
        ▼
   採点               選手項 + ペア項 + 試合項 + ラウンド項
        │
        ▼
   先読み             上位16候補を1ラウンド先まで進めて累積で比べる
        │
        ▼
   コート・チーム・並びのシャッフル
```

## 3. 統計は毎回スナップショットから導出する

採用したラウンドごとに、その時点の全メンバーの状態を1行ずつ記録する
（`played` / `sat_out` / `resting`）。出場回数などはメンバー行に累積せず、
毎回この記録から計算し直す。

- 二重計上や更新漏れが構造的に起きない
- 「間違って開始を押した」の取り消しが、ラウンド行の削除だけで済む
- 不採用ラウンドは記録を持たないので、統計に一切影響しない

導出規則（`stats_rules.py`）:

| 値 | 定義 |
|---|---|
| `plays` | `played` の数 |
| `rest_credit` | `resting` の**連続ブロック**ごとに、「休んでいる間に他の人が増やした出場回数の見込み − 1」（0 未満にしない）を足した総和。端数を含む |
| `sit_out_streak` | 末尾から続く `sat_out` の数 |
| `just_returned` | 現在 active かつ直近の記録が `resting` |
| `adjusted` | `baseline + plays + rest_credit`（端数を含む） |

`rest_credit` が仕様の肝になっている。休憩のまとまり1つにつき、休まなかった人との差が
ちょうど1試合分に留まるようにする。こうしないと、休んだ分を取り返すために連続出場
させられて、また疲れて休むことになる（仕様: 休んだ分は取り戻させない）。

**見込みは、休んでいた各ラウンドの出場の割合の合計**（出場の割合 = そのラウンドに出場した
人数 / 出場可能で休んでいない人数。記録から導出する）。全員が毎ラウンド出る構成では割合が 1
なので、3ラウンドまとめて休めばみなし出場は2回分（長さ − 1）になる。出番待ちが多い構成では
割合が小さいので、長さ − 1 だと過大になる。以前はそうしていたため、16名2面（1ラウンドに
半分が出る）で6ラウンド休むと、戻った人が「休まなかった人より出ている」扱いになり、
戻ってから4ラウンド目まで出番が無かった。割合で割り引くと、**普段の出番待ちより長く休んだ
人だけが、戻った直後に出る**（皆が2試合休んで1回出る構成なら、3試合以上休んだとき）。
短く抜けた人は、出番待ちの人と同じ扱いで、損も得もしない。

みなし出場は端数を丸めずに持つ。その段階で切り捨てると、休憩での欠損が1試合分を超えて
開き、戻った人に取り戻させてしまう。ただし生成の出場の枠と評価関数には `adjusted` を
**四捨五入した値**を使う（`PlayerStat.adjusted_rounded`）。端数のまま使うと、ほぼ全員の値が
ばらばらになって同じ値の人の中から入れ替える余地が消え、ばらけが落ちる。スコアも整数のまま
保てる。その丸めの分、実際の欠損は1試合分から ±0.5 試合分未満ずれるが、偏りは無い
（切り捨てにすると、端数の分だけ決まって余計に取り戻す。16名2面で5ラウンド休むと平均 +1.13 試合）。

離脱していた期間は記録が無いので、ラウンドの通し番号が飛んでいるところで休憩の
まとまりを切る（「休憩 → 離脱 → 戻ってすぐ休憩」を1つのまとまりにしない）。

`baseline` は途中参加者の下駄で、参加登録時点の active メンバーの `adjusted`（四捨五入）の
最小値。これが無いと、遅刻者が追いつくまで何ラウンドも連続出場してしまう。
離脱から戻った人も同じ扱いで、戻った時点で `adjusted`（四捨五入）がちょうど最小値になるよう
下駄を決める（離脱前の出場回数とみなし出場を差し引く）。離脱前の休憩で積み上がった不足は帳消しになる。

## 4. 出場者は公平性のハードな枠で絞る

`adjusted` の小さい順に並べ、出場枠数 N 番目の値を閾値とする。

- 閾値**未満**の人 … 必ず出す（確定枠）
- 閾値**ちょうど**の人 … 入れ替え可能枠。ここから残りを選ぶ

これで参加回数の差は必ず 1 以内に収まる。組合せ数が多いときは
決定的な乱数でサンプリングする（既定 60 通りまで）。

`fairness_slack` を 1 以上にすると「1試合分多く出ている人」も候補に含められるが、
既定は 0（厳密公平）。当初は「候補が1通りしかない局面では枠を広げてばらけさせる」
適応ルールを入れる設計だったが、実測すると**ばらけ方は改善せず公平性だけ悪化した**
ので取りやめた。出場者が1ラウンドおきの交代になっても、コート内のペアの組み方は
自由に選べるためばらけ方は落ちない。

## 5. 組み分けは1試合ずつ決める

**コート数に依存しない構造にしてある。** 1ラウンドを全コートまとめて全列挙すると、
コート数の指数で組合せが爆発するため。

| 出場者 | コート | 組み分けの総数 |
|---|---|---|
| 4人 | 1面 | 1 |
| 8人 | 2面 | 35 |
| 12人 | 3面 | 5,775 |
| 16人 | 4面 | 2,627,625 |

そこで「まだ決まっていない人のうち先頭の人」を必ず次の試合に入れる、という順で
1試合ずつ決めていく。こうすると同じ分け方を数え直さずに済む。

**この「先頭」の並べ方が品質を左右する。** 制約の強い人（初心者 → ルール未習得 →
その他）を先に置く。後ろに回った人ほど選択肢が残らないので、初心者が末尾に固まると
最後の組で避けようがなくなり、仕様3a（初心者同士ペア）を破ってしまう。
初心者は公募で後から登録されるため id が大きくなりやすく、id 順に並べていた時期は
12人3面で 24/36 ラウンド、16人4面で 11/12 ラウンドで初心者同士ペアが出ていた。
同じ制約どうしは id 順に並べる。ここを `tie_key` 順などに変えると、レベル差の無い
練習会でも探索の道筋が変わり、ばらけ（優先度1）が落ちる。id 順でも偏りは出ない。
刈り込みの同点は `tie_break` が id と無相関に決めるので、id の小さい組だけが
生き残ることはない。
**コートごとに独立に決めているのではなく、組み分け全体をビーム探索している。**
1試合決めるごとに安い順へ刈り込むが、複数の候補を並行して保持する。

4人が決まれば、その中のペアの分け方は3通りしかないのでその場で決めてよい。
どう分けても他の試合には影響しないため、全体の最適解を損なわない。

### 刈り込みで最適解を落としていないか

人数がちょうど「コート数 x 4」だと、最後の1試合は残った4人で強制的に決まる。
そのぶん自由度が無く、レベルや男女の条件を満たしにくくなる。
この状況で、刈り込み幅64のビーム探索を全通り探索と突き合わせた結果:

| 構成 | 厳密解 | ビーム探索 | 差 | 組み分けの全通り |
|---|---|---|---|---|
| 2面8人 ラケット経験者4 | 960 | 960 | **0** | 35 |
| 2面8人 初心者1・ラケット3 | 2,020 | 2,020 | **0** | 35 |
| 2面8人 初心者2・ラケット2 | 1,260 | 1,260 | **0** | 35 |
| 3面12人 ラケット6 | 1,440 | 1,440 | **0** | 5,775 |
| 3面12人 初心者2・ラケット4 | 1,740 | 1,740 | **0** | 5,775 |
| 3面12人 初心者3・ラケット3 | 2,680 | 2,680 | **0** | 5,775 |
| 4面16人 ラケット8 | 1,920 | 1,920 | **0** | 2,627,625 |
| 4面16人 初心者3・ラケット5 | 3,160 | 3,220 | +60 | 2,627,625 |

**この表は履歴が空のラウンド1で測ったもの**で、そのときは1〜3面が厳密解に一致した。
2面は35通りが刈り込み幅に全部収まるため。3面も、組み分けのコストが試合ごとに
分解できるので部分和での刈り込みが効いた。

**履歴が溜まると事情が変わる。** ペア重複や初心者の集中が効いてくると、部分コストの
安さと全体の安さがずれ、刈り込み幅64では優先度5（初心者ペアの集中）の最良を落とす。
12人3面・初心者3名・24ラウンド・10シードの実測:

| 刈り込み幅 | 片側だけ初心者の試合/ラウンド（理想 1.0） | ばらけの理論超過 | 所要 |
|---|---|---|---|
| 64 | 2.07 | 0.076 | 85ms |
| 128 | 2.02 | 0.071 | 91ms |
| **512（採用）** | **1.73** | 0.080 | 96ms |

ばらけ（優先度1）がわずかに悪化するが、集中（優先度5）の改善の方が大きいので 512 を採る。
なお**仕様3a を守っているのは刈り込み幅ではなく上記の並べ替え**で、並べ替えを入れれば
64 でも初心者同士ペアは 0 件になる。幅を上げるのは優先度5のためだけ。

### 所要時間

実測（1生成あたり、単独実行。2026-09、24ラウンド x 3シードの平均）。
`uv run python scripts/bench_generate.py` で同じ条件で測れる（既定の構成は下の表の一部）:

| | 2面 | 3面 | 4面 |
|---|---|---|---|
| 8〜10名 | 20〜45ms | — | — |
| 12〜13名 | 90ms | 65〜180ms | — |
| 16名 | — | 300ms | 240ms |
| 20名 | — | — | 0.9〜1.0秒 |

24名と20名3面は測っていない。値はマシンの負荷で1〜2割ぶれる（20名4面は1秒を超える回もあった）。

1試合7分なので、押してから1秒未満で出れば支障はない。

時間の大半は組み分けの探索で、刈り込みで**捨てる**候補の扱いが支配的だった
（16名4面では1回の生成で約130万件の候補を作り、各段で残すのは512件）。
捨てる候補には組み分けのタプルも同点ほぐしのハッシュも作らないようにして、
結果を変えずに 3面以上で2〜3.5倍速くした（20名4面は 3.0秒 → 約0.9秒）。
それ以前の同じマシンでの値は、13名3面 360ms、16名4面 590ms、20名4面 3.0秒。

## 5-2. レベルと「ペアの強さ」

レベルは3段階。**ルールを覚えているかどうか** が分かれ目になる。

| レベル | ルール | 説明 |
|---|---|---|
| 初心者（ラケット未経験） | 知らない | 一日やってもボールを返せないことが多く、ゲームが成立しない |
| ラケット経験者（ルール習得中） | 知らない | 1試合終わるころには返せるようになり、ゲームは一応成立する |
| ピックルボール経験者 | 知っている | — |

ラケット経験者が慣れたら、管理者がレベルを変更する運用。

**ペアの強さ** はレベルと性別の2軸で見積もる。単純な大小は
初心者 < ラケット経験者 < ピックルボール経験者 だが、
初心者とラケット経験者の差は、ラケット経験者とピックルボール経験者の差より
ずっと大きい（3倍程度）。その比を整数で表すため、次の点数にしてある。

| | 初心者 | ラケット経験者 | ピックルボール経験者 |
|---|---|---|---|
| レベル | 0 | 6 | 8 |
| 性別の加点 | なし | 男 +2 / 女 0 / その他 +1 | 同左 |

男女の不均衡1人分が、ラケット経験者とピックルボール経験者の差と同じくらい、
という見立て（= 2ポイント）。**初心者は男女を区別しない**。
ボールが返せるかどうかの段階なので、パワーの差が意味を持たないため。

ペアの強さは2人の合計（0〜20）。これを使って、
「ルールを覚えていない者どうしのペアを避ける」と
「左右のペアの強さの差を減点する」の2つを効かせる。

### 途中でレベルを変えたとき

練習会の最中にレベルを変える運用（ラケット経験者が慣れた、登録を間違えた）が前提にある。

- **ペアの回避規則は、次の生成からすぐ新しいレベルで効く**
- **過去の履歴は、当時のレベルのまま動かさない**。
  「初心者と組んだ回数」は `round_participation.level` に残した
  そのラウンド時点のレベルで数える

固定しないと、過去の全ラウンドが「今のレベル」で解釈し直されてしまう。
昇格させればその人と組んだ負担が帳簿から消え、降格させれば組んでもいない負担が
遡って計上される。どちらも「初心者と組む回数を非初心者の間で均す」規則を狂わせる。

13人3面・20ラウンド、8ラウンド目に1人だけ変更、同一シード4組で測った結果。

| | 生成器が見る履歴の誤差 | 受け持ち回数の幅 |
|---|---|---|
| 昇格（初心者→ピックルボール経験者）・固定する | 0回 | **5.00** |
| 昇格・固定しない | 6.0回 | 5.75 |
| 降格（ピックルボール経験者→初心者）・固定する | 0回 | **1.25** |
| 降格・固定しない | 6.5回 | 2.00 |

1人変えただけで履歴が6回分ずれる。同一シードで並べた8組のうち、
固定したほうが悪化したものは無い（同点4・改善4）。
幅の差が0.75程度に留まるのは、その後のラウンドで生成器が均し直すため。
変更した直後の数ラウンドほど歪みが大きい。

なお**表示中のマッチは動かさない**（不変則12）。
出場中の人のレベルが変わったときは、全体表示画面に注意書きを出して伝える。

## 6. 採点

スコアは低いほど良い。**1試合ごとのコストの和に厳密に分解できる**ようにしてある。

分解の鍵は、優先度2・3・7（参加回数の公平、連続不参加、休み明け）の扱い。
これらは本来「出場しなかった人への減点」だが、そのラウンドで出す人数は決まっているので、
出場者と非出場者の減点の合計は定数になる。そこで符号を反転して「出場者への加点」に
まとめ直してある。近似ではなく等価な変形。

（この定数は1ラウンドの中では順位に影響しないが、先読みでは分岐ごとに状態が変わり
定数も変わるので、累積コストを比べるときは足し戻す必要がある。）

重複回数を均すために、増分を `2c + 1` の形にしてある。これを足し合わせると `c²`
になるので、**二乗和の最小化＝回数の均等化**になる。

| 仕様の優先度 | 項目 | 計算 | 既定の重み |
|---|---|---|---|
| 1 | ペアの重複 | 4ペアそれぞれ `w x (2c + 1)` | 120 |
| 1 | 対戦の重複 | 8組それぞれ `w x (2c + 1)` | 60 |
| 1 | 早すぎるペア重複 | 組んだことのあるペアで、2人とも未ペアの組める相手が残っていれば `w` | 500 |
| 1 | 同じ4人 | その4人で試合をした回数 x `w`（ペアの分け方は問わない） | 240 |
| 1 | 直近の同じ3人 | 直前のラウンドのどれかの試合と3人以上同じなら `w` | 120 |
| 2 | 参加回数の公平 | 出場者それぞれ `w x (2 x adjusted + 1)` | 100 |
| 3 | 連続不参加 | 非出場者それぞれ `w x (streak + 1)²` | 120 |
| 3a | 初心者同士ペア | 両方初心者なら `w` | 100,000 |
| 3b | 初心者 x ラケット経験者 | `w` | 20,000 |
| 3c | ラケット経験者同士 | `w` | 5,000 |
| 4 | 初心者の相手の偏り | 初心者と組む非初心者に `w x (2c + 1)` | 120 |
| 5 | 初心者ペアの集中 | 初心者が片側だけの試合の数 x `w` | 1,000 |
| 5a | ペアの強さの差 | 試合ごとに `w x (強さA と 強さB の差) ` | 15 |
| 6 | 男女構成 | 試合ごとに下表 x `w` | 60 |
| 6a | 男子ペア対女子ペア | 別枠 | 20,000 |
| 7 | 休み明け優先 | 非出場の休み明け1人につき `w` | 40 |
| — | スキップした編成 | 一致したら `w` | 50,000 / 5,000 |

男女構成の係数（`w` を掛ける）:

| 構成 | 係数 | 仕様 |
|---|---|---|
| 男女ペア 対 男女ペア | 0 | 6（最良） |
| 男子ペア対男子ペア / 女子ペア対女子ペア | 1 | 6b（人数が偏ったときの調整として最良） |
| 男女ペア 対 単一性別ペア | 2 | 6c（次点） |
| 男子ペア 対 女子ペア | 別枠 20,000 | 6a（実質禁止） |

補足:

- **初心者を含むペアと、その他/未回答を含むペアは男女構成の評価から外す**（仕様 6d）。
  初心者が入る試合は育成目的なので構成を問わない。これで「初心者を集める」目的と
  「男女ペア同士にする」目的が衝突しなくなる。
- **男子ペア対女子ペアだけ桁が違う**のは、少数派の性別を各ペアに散らせば必ず回避できて、
  この構成が必要になる場面が無いから。初心者同士ペアも同じ理由で実質ハード制約にしてある。
- **ルールを覚えていない者どうしのペアは3段階**で避ける。初心者同士が最も強く、
  次に初心者 x ラケット経験者、最後にラケット経験者同士。ラケット経験者は1試合で
  慣れるので、組ませてしまっても傷が浅いため。避けられない構成（全員ラケット経験者など）
  では大きな有限の減点として degrade する。
- **ペアの強さの差**の重みが小さいのは、仕様でばらけ（優先度1）の方が上だから。
  実測では 0→15 で強さの差が 0.92→0.79 になり、変異性の超過は +1.5pt。
  15→30 は差 0.14 の改善に +2.5pt かかって効率が落ちるので 15 にしてある。
- **初心者ペアの集中**は「片側だけに初心者がいる試合の数」を数える。こうすると
  初心者2名を同じ試合の対面に置く編成が、初心者1名だけを出す編成より良いと評価され、
  結果として初心者は偶数で同時に出す方向へ自然に誘導される。
  初心者が入る試合は、経験者が手加減する育成試合になる。必要なことだが楽しいとは
  限らないので、初心者どうしを対面に集めて育成試合を減らし、その負担を経験者全員で
  分かち合う。初心者どうしのカードはいずれ尽きるので、集められるうちに使い切り、
  差のある試合を後回しにする（初心者が慣れる時間も稼げる）。
  重みは 700 から 1,000 に上げた。700 だと早すぎるペア重複と競合して、10名2面・
  初心者2で片側だけの試合が9ラウンド目から出た。1,000 なら14〜15ラウンド目以降で、
  ピックルボール経験者の育成回数のばらつき（標準偏差）も 700 のとき以下になる。
- **早すぎるペア重複**は、まだ組んでいない相手がいるのに同じ相手と2回目を組むことへの
  減点。同じ相手とのペアは当人が必ず気づくので、対戦の重複よりずっと目立つ。
  ペアと対戦の `2c + 1` だけでは足りない。ペアの重複1つを避けると対戦の重複を
  2つ以上抱えることが多く、「対戦相手を変えるためにペアを繰り返す」判断が起きていた
  （16名4面で、組める相手15人のうち6人目で重複する人も出た）。
  重みは初心者ペアの集中（1,000）より小さくしてある。大きくすると、初心者を含む構成で
  初心者のペアを対面に集められなくなり、強さの差が10もある試合が出る。
- **同じ4人**と**直近の同じ3人**は、早すぎるペア重複の逃げ道を塞ぐ。同じ4人を
  組み替えれば（ab|cd → ac|bd）ペアは全部新しくなるので、ペアの減点だけだと
  同じ顔ぶれの試合に集中する（16名4面で24ラウンド中10ラウンド目から再同席が出た）。
  同じ顔ぶれで固まると、皆で集まってやっている感が薄れる。
  重みは 早すぎるペア重複 500 > 同じ4人 240 > 同じ3人 120 の順。同じ3人は長い目で見れば
  避けきれないので、直前のラウンドに続けて起きる場合だけを見る。
  どれも「この顔ぶれで前に試合をしたか」だけで決まるので、結果を説明しやすい。
  代償として8名2面では、同じ4人を避けるぶんペアの早すぎる重複が1人1回ほど残る
  （分け方が35通りしかなく、両方を同時には満たしきれない）。

## 7. 先読み

1ラウンドの最小解を積み重ねても、練習会全体では最小にならない。
今このペアを使うとその先で組める相手が減る、という近視眼が起きるため。

そこで上位16候補それぞれについて、1ラウンド先まで貪欲に進めて累積コストで比べ直す。
候補ごとの先読みには同じ乱数種を使い、同じ運の下で比較する（共通乱数法）。

生成はボタン1回につき1度で、試合間隔は7分ある。速度より品質を優先してよい。

実測（9構成 x 8シードの対応比較。重複回数の二乗和が理論最小値をどれだけ超過するか）:

| | 平均超過 | 1生成 |
|---|---|---|
| 貪欲（先読みなし） | 16.9% | 25ms |
| 先読み1・上位16候補 | **15.3%** | 100ms |

9構成すべてで改善した。深さ2以上や上位48候補にしても改善しない（先の手の読みが粗いため）。
評価する出場者集合を増やすとかえって悪化する（今のラウンドだけを見て選ぶほど近視眼が強まる）。

## 8. 並び順が透けないようにする

類似ツールにありがちな「登録順や id 順がマッチに透けて見える」「同じ人数だと
毎回同じ展開になる」を構造的に潰してある。

- **練習会ごとの固定シード** — 作成時に採番して以後不変。生成の乱数は
  `(シード, ラウンド番号, 試行回数)` から決定的に導出する。同じ操作なら完全に再現し、
  練習会が変われば同じ顔ぶれでも別の展開になる。試行回数が増えるので
  スキップのたびに必ず別の抽選になる。
- **順序の正規化** — アルゴリズムの入口で、シードと member_id から決まる
  `tie_key` で並べ替える。呼び出し側がどんな順序で渡しても結果は同じで、かつ
  内部の走査順が出力に漏れても登録順には見えない。
- **同点は一様抽選** — 並べ替えのキーに乱数を混ぜて、同点集合から一様に選ぶ。
  先頭採用もしないし、浮動小数の微小ジッタも使わない（スコアは整数のまま）。
- **表示のシャッフル** — どの編成をどのコートに置くか、チームの左右、ペア内の並びも
  シャッフルする。強い人がいつも左、登録が早い人がいつも先頭、を防ぐ。

## 9. 品質の測り方

重みを変えると「重み付き合計コスト」も変わるので、それでは配分どうしを比べられない。
そこで **重複回数の二乗和が、同じ総数を可能なペアすべてに均等配分したときの
理論最小値からどれだけ超過しているか** を指標にした。重みに依存しないので公平に比べられる。

最終的な実測（5〜16名の12構成、3時間ぶんの24〜25ラウンド）:

- 参加回数の差 0〜1
- 連続してマッチに入れない回数 2以下
- 初心者同士ペア 0件、初心者 x ラケット経験者ペア 0件。
  ラケット経験者同士は、回避できない構成でのみ発生する
- 初心者ペアの同一コート集中 90〜94%
- 左右のペアの強さの差は平均 0.8（20点満点の尺度）
- 男子ペア対女子ペア 0件
- **全員が他メンバーのほぼ全員と同じコートに入る**（16名24ラウンドで、1人あたり15人中14〜15人。全員必達は回り方次第で保証できない）
- 1生成あたり 16名までは0.3秒以下、20名4面は約1秒（「所要時間」を参照）

ばらけの見え方（2026-09 の再計測。5〜20名の14構成 x 4〜8シード、24ラウンド）:

- **まだ組んでいない相手がいるのに同じ相手と組む**（早すぎるペア重複）は、初心者のいない
  構成で1人あたり 0.1〜1.0回（旧方式は 0.8〜1.4回）。16名4面は15ラウンドのうち、
  13シード中11シードで0組。
  残るのは一巡の終わり際（12名3面なら11人中8回目以降）か、初心者・ラケット経験者が
  多く組める相手が構造的に限られる構成（13名に初心者3・ラケット2 など）
- **同じカード（同じ2ペアどうし）の再発**は、5〜6名1面を除き 0〜1件
  （旧方式は 8名2面で1回の練習会あたり約3件）
- **同じ4人の再同席**は 0〜3件（旧方式は 8名2面で約10件、16名4面は10ラウンド目から）
- 代わりに**対戦相手の偏り**の理論超過は、16名4面で 7%→12%、20名4面で 16%→27% に増える。
  当人が気づきやすいペアと顔ぶれを優先した結果

## 10. 調整できるところ

環境変数か `app/config.py` で変えられる。

| 名前 | 既定 | 意味 |
|---|---|---|
| `FAIRNESS_SLACK` | 0 | 何試合分まで多く出ている人を候補に含めるか。0 は厳密公平 |
| `LOOKAHEAD` | 1 | 何ラウンド先まで読むか。0 なら貪欲 |
| `BEAM` | 16 | 先読みで比べる上位候補の数 |
| `MAX_CANDIDATE_SETS` | 60 | 評価する出場者集合の上限 |

コート数が増えると1ラウンドの組み分けが一気に増えるので、
候補集合の数と先読みの幅は内部で自動的に絞られる。よく使う2面までは絞らない。

スコアの重みは `app/scheduler/domain.py` の `Weights`。

## 11. あえてやっていないこと

- **細かい実力の反映** — レベルは3段階と性別しか見ていない。同じ「ピックルボール
  経験者」の中での上手下手は扱わない。勝敗も記録していないので、成績からの推定もしない。
- **練習会全体の事前設計** — 16名なら組合せ論的に理想的な日程表（アフィン平面）が
  存在するが、遅刻・中座・休憩でメンバーが変わる前提では組めない。
  毎ラウンド組み直す方式を採っている。
- **タイマー** — 仕様により後回し。
